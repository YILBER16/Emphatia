# Sprint 0 — Preparación de entorno

## Objetivo del sprint

Que **cada módulo arranque en el PC del estudiante** y que el equipo entienda el mapa.  
**No** se desarrollan funcionalidades nuevas. **No** se cambian contratos.

## Resultado esperado (equipo)

- Cada rol completa su misión M0 y su checklist.  
- En el PC piloto (o el de B): servicios mínimos “up” y/o prueba de humo OK.  
- Nadie mergea features: solo docs de aprendizaje del estudiante (APRENDIZAJE.md, notas) y setup.

## Orden recomendado

1. [M0-COMUN](./M0-COMUN-repo-y-herramientas.md) (todos)  
2. En paralelo: [M0-A](./M0-A-entorno-unity.md) · [M0-B](./M0-B-entorno-laravel.md) · [M0-C](./M0-C-entorno-inteligencia.md) · [M0-D](./M0-D-entorno-expresion.md)  
3. [Checklist de integración](../../checklists/sprint-0/checklist-integracion-equipo.md)

## Definition of Done — Sprint 0

- [ ] Checklists individuales A/B/C/D en verde  
- [ ] Checklist integración en verde  
- [ ] Cada estudiante puede explicar su caja del [PROJECT_MAP](../../PROJECT_MAP.md) en 30 segundos  
- [ ] No se rompió la prueba de humo del piloto (si se tocó `servidor/`)

## Fuera de alcance (explícito)

Login real en Unity, InferTurn con modelos reales, lip-sync, MySQL obligatorio, WebSockets, cambios en `contratos/`.
